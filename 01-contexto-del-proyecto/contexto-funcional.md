# Contexto funcional del proyecto

Este caso práctico consolida tres escenarios anonimizados de sistemas corporativos en un único flujo de portfolio QA.

## Dominio simulado

La solución representa una plataforma empresarial con módulos de:

- administración de usuarios, roles y permisos;
- reportes analíticos y dashboards de Business Intelligence;
- validación de identidad durante procesos de onboarding.

## Alcance QA

El objetivo del análisis es validar que los módulos cumplan reglas de negocio críticas, mantengan consistencia de datos y reduzcan riesgos funcionales antes de una liberación.

## Supuestos

- Los escenarios fueron adaptados para portfolio y no corresponden a información confidencial real.
- Las evidencias de ejecución y defectos son simulados, creados para demostrar metodología QA.
- La automatización y validación API se incorporarán progresivamente.

## Riesgos principales

- Accesos indebidos por errores en permisos.
- Perdida o inconsistencia de datos en dashboards y exportaciones.
- Fallos de validación de identidad que impacten el onboarding.
- Falta de trazabilidad entre requisitos y pruebas.

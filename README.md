# Portfolio QA - Especificaciones funcionales y trazabilidad

Este repositorio presenta un caso práctico de QA funcional y análisis de requerimientos basado en escenarios profesionales anonimizados, generalizados y adaptados para portfolio.

> Nota de confidencialidad: este material no contiene información real ni confidencial de clientes. Los escenarios fueron modificados para proteger acuerdos de confidencialidad y se usan exclusivamente para demostrar metodología de trabajo QA.

## Objetivo

Demostrar mi capacidad para transformar necesidades de negocio en artefactos QA trazables: FSD, historias de usuario, reglas de negocio, precondiciones, criterios de aceptación, escenarios Gherkin, matriz de trazabilidad, evidencias de ejecución, bugs encontrados y validaciones API con Postman.

## Rol representado

QA Analyst / Functional Analyst, con foco en:

- análisis funcional;
- validación de requisitos;
- diseño de casos de prueba;
- testing funcional y end-to-end;
- trazabilidad entre requisitos y pruebas;
- comunicación de bugs encontrados;
- validación de APIs y datos como línea de evolución profesional.

## Cómo revisar el proyecto

1. Leer el contexto funcional y el FSD.
2. Revisar cada historia de usuario.
3. Consultar los casos de prueba en Gherkin.
4. Validar la cobertura en la matriz de trazabilidad.
5. Revisar evidencias de ejecución manual simulada.
6. Revisar los bugs encontrados para entender análisis de impacto, severidad y prioridad.
7. Revisar `06-postman/` para validar la evidencia API complementaria.

## Nota sobre la evidencia Postman

La evidencia de Postman corresponde a una API demo de tienda deportiva. En esta primera versión se cubren principalmente flujos de autenticación y perfil de usuario.

No está conectada directamente con las historias de usuario funcionales de las carpetas anteriores; se incluye como evidencia complementaria de API testing.

A futuro, la cobertura Postman puede ampliarse hacia otros módulos de la tienda deportiva, como productos, carrito, órdenes y pagos simulados.
